## Why this mission exists

Mission 007 is complete, but the dependency-security remediation performed afterward exposed one blocking compatibility break before Mission 008 should begin.

Observed local remediation state on 2026-08-29:

- frontend `npm audit`: **0 vulnerabilities**;
- frontend production build: **PASS, 432 modules transformed**;
- Python `pip-audit`: **No known vulnerabilities found** after the security upgrades;
- Starlette upgraded from **0.50.0 to 1.6.0**;
- MCP resolved to **2.1.1**;
- backend test collection then stopped with **6 collection errors** because inherited MCP code still imports the MCP 1.x API `mcp.server.fastmcp.FastMCP`;
- MCP 2.x reports that `FastMCP` was renamed to `MCPServer` and other APIs changed.

## Objective

Migrate the existing inherited MCP integration to the current MCP 2.x API so ModelMix can keep the security-clean dependency set without carrying an avoidable MCP 1.x compatibility pin.

This is a compatibility/security interlock only. It does **not** promote MCP into ModelMix alpha product scope.

## Changes Made

1. `the_ai_counsel_mcp/server.py`:
   - Migrated from `mcp.server.fastmcp.FastMCP` to `mcp.server.mcpserver.MCPServer`.
   - Initialized `MCPServer` with `name`, `version`, and `instructions`.
   - Updated `run_stdio` and `run_sse` to use `MCPServer.run_stdio_async()` and `MCPServer.run_sse_async(host=host, port=port)`.
2. `the_ai_counsel_mcp/stream_buffer.py`:
   - Updated `wrap_with_progress(events, ctx=None)` to accept optional context and safely handle progress/logging without importing removed `mcp.server.lowlevel.server.request_ctx`.
3. `the_ai_counsel_mcp/tests/conftest.py`:
   - Updated `get_text` helper to handle MCP 2.x `CallToolResult` objects (`call_tool_result.content[0].text`).
4. `the_ai_counsel_mcp/tests/test_server.py`:
   - Updated handshake version assertion to read from `server._lowlevel_server.create_initialization_options().server_version`.
